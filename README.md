# 水下遗址回淤监测与清淤建议

直接打开 `index.html` 使用（无需构建、无需服务器）。标记、回淤测量批次、清淤建议挂在同一基准面版本上，清淤队只依据当前有效建议开工。

## 三个业务模块

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 规则模块 | `js/rules.js` | 校准有效性、读数合并、同时冲突、建议计算。纯判断，不碰存储和页面 |
| 批次存档模块 | `js/archive.js` | 批次事务合并、操作号幂等、检查点恢复、基准版本、审计留查 |
| 页面操作模块 | `js/app.js` | 地图、表单、批次提交、冲突处理、建议展示 |

## 规则要点

- 每笔测量带**操作号、设备校准号、测量时刻、基准面版本**；同号重传只认首次。
- 只有**校准有效且基准一致**的读数参与当前淤积判断；其余留查不进建议。
- 合并按测量时刻定新旧，**旧读数不再覆盖新值**。
- 两船同一时刻报同一标记且厚度不同 → 冲突：**暂留现场值**，处理前该标记不进清淤建议。
- **基准面或标记位置一变，建议立即失效重算**，原读数与历史建议全部留查。
- 批次合并失败 → 整批回滚，**从最后确认标记（检查点）恢复**；也可手动恢复。
- 旧数据缺基准面版本 → 先归**待补测**；在当前基准下复测后自动归位。

## 演示流程（回淤测量页）

1. **演示两船批次**：A 船报 2 笔；B 船报 3 笔——同一标记同时异值（冲突，留现场值）、校准过期（不参与判断）、同号重传（只认首次）。
2. 到**清淤建议**页处理冲突（保留现场值 / 采用甲 / 采用乙），标记回到建议。
3. **模拟故障批次**：未知标记导致整批回滚，审计日志记录从检查点恢复。
4. 头部**变更基准**：建议立即失效重算，旧读数留查，全部标记归待补测；重新提交测量即在新基准下归位。
