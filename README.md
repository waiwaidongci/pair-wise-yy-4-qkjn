# 水下遗址回淤监测系统

直接打开 `index.html` 使用。系统把**标记、回淤测量批次、清淤建议**接到同一基准面，解决两船合并时旧读数覆盖新值、清淤队按过时依据开工的问题。

## 业务规则

- **每笔测量带齐四要素**：操作号、设备校准号、测量时刻、基准面版本。
- **同号重传只认首次**：按操作号去重，重传读数忽略不计。
- **只有校准有效且基准一致的读数能参与当前淤积判断**：校准过期或基准已变更的读数只存档、不参与判断。
- **两边同时提交同一标记时保留现场值**：两船在同一轮次都测了同一标记 → 冲突，现场值（最后确认标记）保留，该标记**不能进入清淤建议**；冲突处理后才解锁。
- **基准或标记位置一改，建议立即失效重算，原读数留查**：启用新基准面或拖动标记后，全部相关建议失效并按新基准重算，原始读数在批次存档中可查。
- **合并失败后从最后确认标记恢复**：整批事务回滚到上一轮确认的现场值。
- **旧数据缺少基准时先归待补测**：没有基准面版本的读数 / 标记进入待补测，不进入建议。

## 三个业务模块（`js/`）

| 文件 | 模块 | 职责 |
| --- | --- | --- |
| `rules.js` | 规则模块 | 基准面版本、设备校准有效性、淤积判定、建议失效规则 |
| `archive.js` | 批次存档模块 | 测量批次与原始读数存档、同号去重、合并事务、失败回滚、冲突处理 |
| `app.js` | 页面操作模块 | 标记地图、清淤建议、冲突处理、待补测、批次存档、规则面板 |

## 页面操作

- **左船 / 右船提交批次**：模拟两船各自提交回淤测量批次。
- **完成本轮合并**：确认现场值，作为下次合并失败时的恢复依据。
- **重传演示**：重传已有批次，验证同号重传只认首次。
- **演练合并失败**：提交含未知标记的批次，验证整批回滚到最后确认标记。
- **规则页签**：启用新基准面（建议失效重算）、查看/新增设备校准、调整淤积阈值。
- **批次存档页签**：查看每批原始读数、应用/冲突/待补测/重传计数与失败原因。
- **冲突页签**：采用左船 / 采用右船 / 维持现场 / 标记待补测。
- **地图**：点击空白添加标记（无基准 → 待补测），拖动标记改变位置（建议失效重算）。
- **导出存档**：导出全部状态 JSON。
